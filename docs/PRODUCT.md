# 问对 AskWho · 产品文档

## 产品名称与定位

产品名称：问对 AskWho。

AskWho 是一款 AI Experience Routing 产品。对于难以通过标准知识、普通搜索或通用 AI 可靠回答的生活经验问题，AI 不直接代替真人生成经验，而是理解“什么样经历的人最适合回答”，找到真正经历过的人，以低打扰方式收集回答，并把多个真人经验整理成可用答案。

## 核心原则

- **Answer First，Connection Second。** 产品首先帮助用户解决问题，连接服务于获得可用答案。
- 产品不是陌生人社交产品，不以扩大社交关系作为核心目标。
- AI 负责理解、匹配、路由和整理，不伪造真人经验；整理结果应保留不同经历带来的共识与差异。
- 匹配依据是 **Experience，而不是 Influence**：依据相关经历判断适配度，而不是知名度、粉丝数或影响力。
- **Interest 不等于 Experience**：感兴趣不代表亲身经历过，不能用兴趣标签替代经历依据。

## 核心流程

提出问题 → AI 理解问题 → 提取必要/优先经历条件 → Experience Match → 为不同经历者路由不同子问题 → 匿名经验邀请 → 真人回答 → AI 整理共识和差异 → 回答沉淀为 Experience Asset。

必要经历条件与优先经历条件需明确区分；子问题应根据回答者的实际经历分配。邀请以匿名、低打扰为原则，聚合答案以收集到的真人经验为依据。

## 正式 Demo 的六个核心页面

| 页面 | 职责 |
| --- | --- |
| Ask | 首页提问。 |
| Understand | AI 理解用户真正需要什么 Experience。 |
| Match | 找到真正经历过的人。 |
| Request | 回答者收到低打扰经验邀请。 |
| Answer | AI 聚合多份真人经验。 |
| Experience | 我的经验资产。 |

六个页面是后续正式 Demo 的范围定义，本轮仅完善文档，不实施页面或新增功能。

## Demo 固定案例

> 我第一次一个人去东京看演唱会，也不会日语。东京巨蛋晚上散场以后回新宿会不会特别困难？

后续页面、mock data 和本地模拟逻辑围绕这一案例保持一致，展示从提问、理解与经历匹配，到邀请、回答整理与经验沉淀的流程。

## 当前 Demo 不实现

- 一对一即时聊天。
- 社区 Feed。
- 积分或排行榜。
- 专家问答。
- 真实后端。
- 真实 LLM API。
- 数据库。

## 工程边界

遵守根目录 [AGENTS.md](../AGENTS.md) 的长期工程约束。Demo 使用前端 mock data 和本地逻辑模拟 AI 能力及真人回答流程；模拟内容不冒充实时收集的真实用户回答。核心功能离线可运行，不调用外部 API，不引入后端、环境变量或 API Key。新增 npm 依赖须先取得用户明确同意。
